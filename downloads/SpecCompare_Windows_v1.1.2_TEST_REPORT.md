# SpecCompare Windows v1.1.2 검증 범위

## 변경

PDF 양식마다 규칙을 추가하는 한계를 줄이기 위해, 문서 전체의 모델 목록 해석 후 2페이지씩 글자·이미지를 읽는 AI 분석 경로를 추가했습니다. 새 양식의 의미 해석은 사용자가 연결한 AI 모델이 담당합니다.

- 기본 로컬 Ollama 비전 모델 / 선택 OpenAI Responses API(온라인 동의 필수).
- 영어·한국어 Tesseract fast 데이터 포함, PyMuPDF 내장 OCR.
- 원문 인용, 숫자·단위, 모델 연결, 적용 범위, QD 조건 검사. 단순 문자열 존재 확인은 의미 정확성을 보장하지 않음.
- 제품군 최대값과 모델별 사양 분리. 여러 모델 문서의 모호한 성능 연결은 보류. 수평 용량 표는 좌표 연결도 확인.
- AI 후보는 모두 검토 필요. 실패 시 규칙으로 자동 대체하지 않고 오류 표시. 빠른 규칙 모드는 별도 선택.
- 원본 Excel 비교 양식 유지, 별도 _분석근거.xlsx에 공통·미확정 값/페이지/원문/조건 저장.
- API 키는 이번 실행 메모리에만 보관하고 설정·로그에 저장하지 않음.

## 확인한 내용

로컬 회귀 39개 테스트 통과(실제 PM9E1/PM9A1/990PRO/ESSENCORE/Samsung DDR5 및 Transcend 원문 검증 포함), 추가 식별자 구분·잘못된 응답 타입 검사 2개 통과. 최종 테스트 수 41개. CI는 사용자 PDF 6개가 없어 해당 테스트를 건너뜁니다.

Transcend 테스트는 사람이 구성한 정답 후보를 사용해 원문 인용·5개 모델 구분·공통 최대값을 모델 셀로 복사하지 않는 검증을 수행했습니다. 실제 AI가 Transcend 문서를 정확히 해석했다고 주장하는 테스트가 아닙니다.

AI HTTP 테스트는 정해진 응답을 반환하는 로컬 합성 서버입니다. Ollama 요청·페이지 이미지 전송·JSON 응답·검증·Excel 흐름의 계약 테스트이지, 실제 LLM 해석 테스트가 아닙니다. OpenAI 어댑터는 요청/응답 mock 테스트입니다.

검사 항목: 원문에 없는 값/페이지 거절, 숫자 부분 일치 거절(400 vs 2400), 잘못 연결된 공통 최대값 보류, 수평 표의 올바른 열 연결/바뀐 열 거절, QD별 값 보존, 서로 다른 모델번호 구분, OCR 스캔, Excel 수식 주입 방지, GUI 공통값 분리, AI 실패 시 규칙 자동 대체 금지.

## 미검증·제한

- 실제 로컬/온라인 LLM의 사용자 문서 해석 정확도: 모델·API 키가 없어 미검증.
- 실제 사용자 PC의 Ollama 설치·모델 다운로드·메모리·성능·모델별 JSON/이미지 호환성.
- 모든 PDF 양식, 한국어 스캔 OCR 정확도, 실제 VGA 문서, 일반 사용자 PC/SmartScreen, Microsoft Excel UI.
- 한 번에 최대 100페이지/글자 30만 자. API는 여러 번 호출되며 요금이 발생할 수 있음.
- 로컬 AI 모델은 ZIP에 포함하지 않음. 최초 모델 다운로드와 연결 설정이 필요함.

프로그램에 AI 경로를 구현한 것과 실제 AI 정확도를 검증한 것을 구분합니다. 실제 모델 설정 후 원문 대조가 필요합니다.

Windows v1.1.0 실행 검사 실패로 미배포: https://github.com/shy4938-byte/-/actions/runs/39729427014 . 후속 수정본에서 한글 OCR 경로 캐시·진단 로그·문맥 크기 보호를 보완합니다.

추가 검증: 긴 문서 모델 목록 분할(문자 누락 방지), 로컬 AI 문맥 한도·출력 잘림 오류, 한글 폴더 OCR 언어 데이터 해시 캐시. 최종 테스트 44개(사용자 PDF 6개는 CI 미첨부로 건너뜀). 실제 LLM 미검증 상태는 동일합니다.

사용자 선택 반영: 첫 실행 기본을 온라인 OpenAI API(gpt-4.1-mini)로 변경. 키와 PDF 전송 동의는 앱에서 입력하며 로컬 Ollama는 선택 기능입니다. 실제 PDF 6종을 포함한 최종 로컬 테스트 44개 모두 통과. 실제 LLM으로 읽은 정확도는 여전히 미검증입니다.
